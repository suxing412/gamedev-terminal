## 说明书就是回归条件

`docs/模块.json` 是说明书正本，`docs/说明书.md` 由它生成。

**这份说明书不会漂**，因为 `test/架构/说明书.test.js` 盯着它：

| 你干了什么 | 会怎样 |
|---|---|
| 加了模块没写进说明书 | 红 |
| 说明书写了模块但没建 | 红 |
| 职责写成 `TODO` / 留空 | 红 |
| 声明的导出对不上实际导出 | 红 |
| 模块没有判据，或判据里零断言 | 红 |
| 跨层反向依赖（按**实际 require** 判） | 红 |

三条已实测能红：加文件不声明 / 职责写 TODO / 领域反向依赖编排。

**`待建` 那张表清空之日，就是新仓可以取代旧仓之时。**

## 跑

```bash
npm test        # 全量判据。零断言的套件算红——空套件和全过在「没报错」上长得一样
npm run 说明书   # 从 docs/模块.json 重新生成 docs/说明书.md
```

## 分层

```
内核  形状与落点      可依赖：—
领域  纯函数业务      可依赖：内核        禁 fs / http / child_process
编排  会卡死的那层    可依赖：内核 领域
接口  HTTP           可依赖：内核 领域 编排
哨兵  旁路观测        可依赖：内核        —— 产线死了它还得活着说话
web   浏览器那半      可依赖：—          不 require 服务端，不自算状态分组
```
