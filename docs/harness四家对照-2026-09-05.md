# 二、契约落点

## 上下文包（进）
- **硬落**（机制保证原文送达模型、不经 shell）：Claude SDK（stdin JSON 行，实跑 ●）；codex（stdin `-`，实跑 ●）；Hermes（`--query-file <utf8 文件>` 或 HTTP body，源码 ●）；dsh **仅 SDK JSON-RPC 通道**（`session/prompt` JSON 帧，源码 ●）。
- **软落**：dsh headless CLI——task 只走 argv，编码取决于调用方 shell（◌）。
- **附加目录/工作根**：Claude `cwd`+`additionalDirectories`、codex `-C`+`--add-dir`、Hermes `--in DIR`、dsh 单 cwd。四家都能指定工作根；多目录只有 Claude/codex 有原生字段。

## 权限声明（进）
- **工具级白名单，硬落且可按单传入**：Claude（`allowedTools`/`disallowedTools`/`tools` 每次 query 传，实跑 ●）；codex（`-c` 内联 hooks + `.rules` 命令级，实跑 ●；MCP 工具走 `disabled_tools`）；Hermes（`--toolsets` toolset 级 ●；tool 级要生成临时 config.yaml + `--ignore-user-config`）。
- **工具级只能软落/需自写代码**：dsh——`tools.restrict()` 必须在 `setup(agentCtx)` 里调，即写插件 `--patch` 插入，无配置字段（源码 ●）。
- **目录级**：
  - Claude：`additionalDirectories` 是软闸（只决定自动放行范围）；硬隔离靠 `sandbox`，Windows 未验（◌）。
  - codex：文档上硬（三档沙箱），**本机实证落不到**（elevated 档 UAC 1223 全失败 ●），且沙箱不管 MCP 工具（node_repl 绕过 ●）→ 退化为事后 diff。
  - Hermes：write_file/patch 硬拒（`HERMES_WRITE_SAFE_ROOT` ●），terminal 无目录约束 → terminal 侧退化为 pre_tool_call 自查或 Docker 后端。
  - dsh：单 workspace root，Windows 沙箱 partial（○）；越界 bash 触发 approval，headless 无答者→拒。
- **权限声明外的干扰源**：Claude 本机 settings.json 叠加（`settingSources:[]` 切断，但连 CLAUDE.md 一起切）；codex 项目级 `.codex/hooks.json`/`.rules` 在非 trusted 目录不加载（●）；Hermes 用户 config（`--ignore-user-config` 切）。

## 证据包（出）
- **硬落**（一次进程输出攒齐结构化结果）：Claude（`result` 消息：文本/结构化输出/usage/modelUsage/cost/permission_denials/terminal_reason ●）；codex（`--json` item 流 + `turn.completed.usage` + `--output-schema` 终答 + 退出码 ●；缺口：hook 否决只在 stderr、无 cost）。
- **软落**（进程只吐文本+退出码，用量/工具轨迹须二次回读）：Hermes（回读 state.db 或 `hermes sessions export` 或改走 HTTP `/v1/runs/{id}` ●源码）；dsh（回读 `$DSH_HOME/sessions/.../session.jsonl.zstd`，需先配 `compression:'none'` ●源码）。
- **四家都落不到**：工作区文件 diff 清单——没有一家原生输出，适配器须自做 `git diff` 或在 pre/post 钩子记录写路径。
- **退出码**：codex/Hermes/dsh 有进程退出码；Claude SDK 是 generator，靠 `result.subtype`/`is_error` 映射。

## 会话续接
- **硬落**：Claude（`resume`/`forkSession`/`resumeSessionAt` ●）；codex（`codex exec resume <id>` 实跑 ●）；Hermes（`--resume <id>` ●源码；HTTP 传 `session_id`）。
- **只落一半**：dsh——headless 与 SDK JSON-RPC 服务端都不跨进程 resume，只有 ACP `session/resume`（且不回放历史）●源码。
- **外读会话档**：Claude JSONL ●、codex JSONL ●、Hermes SQLite/export ●源码、dsh 默认 zstd 压缩 ●源码（需改配置）。
- 注意：Claude resume 后 usage 归零（○），跨续接累计须适配器按 session_id 自加。

## 写闸单独说
**四家都有 pre-tool 钩子，写闸都不必退化为纯事后 diff。** 但「谁能从进程外否决」分三档：
1. **原生、按单传入、实跑证实拦下**：Claude（`hooks.PreToolUse` 回调 ●）；codex（`-c 'hooks.PreToolUse=[...]'` 内联 + `.rules` ●）。
2. **原生、但要改配置/环境而非按单传参**：Hermes——shell 钩子写 config.yaml，无头须 `--accept-hooks`，且默认 fail-open 要逐条 `fail_closed: true`（●源码，本体未实跑）。
3. **要写代码才有**：dsh——进程内 Cordis 插件或 `--patch` 挂 `dsh-hooks-claude-code`（默认未挂载）；headless/SDK 通道拿不到进程外否决，只有 ACP `session/request_permission`，且仅在决策为 ask 时触发（●源码）。

**退化情形**：codex 在 `--dangerously-bypass-approvals-and-sandbox` 下 hook 是否仍拦未验（◌）；dsh headless 若不挂插件 → 只剩事后 diff。事后 diff 审计能挡的：工作区内已提交/可 diff 的文件改动可发现并回滚；挡不住的：工作区外写入、网络副作用、已执行的破坏性命令（rm/git push）、MCP 工具绕过（codex node_repl 实证）。

# 三、Hermes 到底是什么

Hermes 是 NousResearch/hermes-agent 仓库（v0.21.0，MIT，Python 3.11-3.13），是一个完整的 agent 运行时/harness，不是模型——同实验室的 Hermes 系列模型是另一回事。它带工具循环、SQLite 会话（FTS5 全文检索含 CJK 分词）、三层 pre_tool_call 钩子、审批层，暴露 CLI/HTTP 网关/JSON-RPC/ACP/Python 内嵌五种入口（programmatic-integration.md:11-15；run_agent.py:467）。归格：它**是**候选 harness 之一，与 Claude SDK/codex/dsh 同列；同时因自带 MEMORY.md/USER.md 有界记忆 + 外部知识库插件 + 会话检索，也适合制作人说的「知识库管理员常驻终端」那一格——但那一格要跑 `hermes gateway` 常驻进程走 HTTP，与按工单单发的 harness 用法是两种部署。本次证据全部来自源码克隆（commit 6327930）与官方 docs，本机未安装未实跑。

# 四、给适配器设计的三条硬建议

1. **写闸只写一份，用 Claude Code 钩子线格式（stdin JSON → stdout `permissionDecision` / exit 2 = 拒）做成独立 gate 进程，四家复用。** 理由：Claude 原生同形状（sdk.d.ts:2380-2392）、codex 原生同格式（learn.chatgpt.com/docs/hooks）、Hermes shell 钩子明写兼容 Claude Code 格式（shell_hooks.py:43-54）、dsh 有 `dsh-hooks-claude-code` 包——四家唯一的公共面就是这个协议，且必须配 fail-closed（Hermes 默认 fail-open，dsh approval 缺答者默认拒）。

2. **证据包以「会话档路径 + 适配器解析出的标准字段 + 适配器自做的 git diff」为主源，进程 stdout 只当校验。** 理由：只有 Claude/codex 有结构化进程输出，Hermes/dsh 必须回读会话档；四家都不吐文件 diff；统一从会话档取 usage/工具序列/终止原因，适配器才能对四家给出同构证据包（codex 还要并收 stderr 补 hook 否决记录）。

3. **每家 pin 精确版本，升级门槛=三条无头冒烟判据跑绿：中文 prompt 原样回显、钩子否决一次 Write、resume 一次续接。** 理由：四家全是 0.x 且日更/周更（Claude 日更 287 版、codex 2-4 天、Hermes 周标签、dsh 两周十 tag），破坏性变更只写 changelog 或根本无 CHANGELOG（dsh），这三条恰好覆盖契约的进/闸/续接三面，红了就是契约断裂。附带：prompt 一律不走 argv（dsh headless 例外则改走 SDK JSON-RPC）。

# 这些是猜的（◌ 格与未验项）

- **Claude SDK**：`sandbox` 在 Windows 的可用性未实测（文档只提 Linux bubblewrap）；file-checkpointing 的 diff API 未核实；SDK 捆绑 CLI 2.1.247 与本机 claude.exe 2.1.227 错位的实际影响未验。
- **codex**：`--dangerously-bypass-approvals-and-sandbox` 下 PreToolUse hook 与 `.rules` 是否仍拦——文档未写、本机分类器拦了实跑；Windows `unelevated` 沙箱档是否能修好无头沙箱未验证；「PS5.1 代码页 936 时 argv 中文风险」是推断（本机 65001 未复现）。
- **Hermes**：**本体未安装未实跑**——`-Q` stdout/stderr 形态、退出码、`hermes_bootstrap` 对 stdin 的 UTF-8 重配是否在 Windows 生效，全是源码读出来的；本机做的 argv/stdin 编码实测对象是裸 python，不是 hermes；shell 钩子 `--accept-hooks` 在无头下的实际行为未验。
- **dsh**：headless argv 中文是否被调用方 GBK 化未实跑；`dsh-hooks-claude-code` 用 `--patch` 挂上后在 headless profile 下是否真的触发未实跑；Windows 沙箱「partial 强制」具体覆盖面未验；本地克隆 alpha.4 与上游 rc.1 的接口差异未逐条核对（工作树截断，靠 `git show HEAD:` 读）。
