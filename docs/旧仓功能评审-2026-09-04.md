# 旧仓功能评审 · 通过的进功能清单

> 2026-09-04。盘的是**功能**（能拿它干什么），不是资产（有什么代码）——资产那份在 legacy 仓 `docs/资产总结-2026-09-02.md`。
>
> **口径**：每条功能过两把刀。**第一性原理**——它解决什么根本问题？那问题在新系统里还在吗？有没有更简单的解法？**对抗性**——构造一个它坏掉、没用、有害的具体场景；构造不出就写「攻不动」，那是通过的最强理由。
>
> **判决四选一**：通过 / 打回 / 待你定 / 并入。空壳与已废默认打回，除非它解决的问题在新系统里仍然存在。
>
> **诚实声明**：这一版是**单人评审**。独立的多代理评审**派了三次，三次全部 529 过载**（22:15 / 22:25 / 22:42，每次三个代理一个字没跑）。所以对抗性那一半是我攻我自己盘的东西，缺独立视角。**这份不是终稿**——API 恢复后要再派一队独立复审，两版对照，分歧处另列。
>
> 证据口径：`L` = 旧终端 `gamedev-terminal-legacy`，`S` = 旧监制台 `Ticketflow/apps/studio`，`P` = `Ticketflow/packages`。

# 七、文档库：自建 vs Obsidian

文档库那一圈是「存储所有 .md · 按标签和类型筛选 · 文件编辑器」。今天查了：你已经开了两个 Obsidian 库（一个今天开的指向整个 GitHub 目录 10444 个文件，一个 7 月开的第二大脑空了 44 天）。

| | 自建（旧终端文稿台 1232 行 + 83 判据） | Obsidian |
|---|---|---|
| 存储所有 .md | 有 | **原生**——它就是读文件夹 |
| 按标签类型筛 | 七类机器猜 + frontmatter 覆写 | **原生**——frontmatter 当属性，Dataview 插件可查表 |
| 编辑器 | 自写 + 版本环 + 记号按钮 | **原生**，且比自写的好 |
| **禁写活存储** | 白名单写闸 | **没有**——它直接写盘，往 `待派/` 里写字它不拦 |
| **与坐席的占用锁** | 租约锁 424 行 | **没有** |
| 类型判定「这是你定的不是我猜的」 | 有 | 没这个概念 |
| 正文四记号全库计数 | 有 | 没有（能用标签模拟，但不是同一件事） |

**推荐：Obsidian 当编辑器与浏览器，写闸与锁留在系统里。** 具体：

1. Obsidian 库指向 `AI-GameStudio`，用它自己的「排除文件夹」把活存储（待派/归档/完成/回执/journal）排掉——**看得见、写不了**
2. 新系统的写闸是唯一写入口，Obsidian 的写是「人手改文档区」这一条路，写闸对文档区放行
3. 租约锁保留：坐席正在改某份文档时，Obsidian 那边人打开它要看到锁（可以用一个 `.lock` 旁文件让 Obsidian 显示）
4. **不自建编辑器。** 旧终端文稿台里值得搬的只有：写闸（已搬）、租约锁、类型判定、四记号统计——1232 行里大约 600 行

代价：类型判定与记号统计要在 Obsidian 之外跑（新系统的 `领域/文稿`），Obsidian 里看不到那两样的结果——除非用 Dataview 把结果表读进来。**这个代价可以接受。**
